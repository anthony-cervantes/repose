= REPOSE - The REstful PrOxy Service Engine

*Repose* is an open-source platform that you can use to build stacks of reusable software
components. These components can be leveraged by service developers to perform
common API processing tasks. By using *Repose*'s components rather than creating their
own, service developers can focus on the unique features of their services.

*Repose* is run as a standalone application (either as a Linux service or using the
JAR directly). *Repose* can be run on the same server or on a different server, and
it can be run across multiple servers for horizontal scaling. At its core, *Repose* is a
proxy that allows services to use Enterprise Integration Patterns (EIP).

For more information, check out our link:repose-aggregator/docs/src/asciibinder/recipes/getting-started.adoc[Getting Started with *Repose*] guide.


== Benefits

* *Scalable*. *Repose* is incredibly scalable because it is designed to be stateless.
* *Flexible*. *Repose* is run as a link:repose-aggregator/docs/src/asciibinder/recipes/valve-installation.adoc[standalone Linux service (Valve)].
* *Extensible*. New link:repose-aggregator/docs/src/asciibinder/filters/index.adoc[components]
  are being added all of the time, and you can even build your own
  link:repose-aggregator/docs/src/asciibinder/recipes/custom-filter-for-repose.adoc[custom component].
* *High performance*. *Repose* can handle link:repose-aggregator/docs/src/asciibinder/recipes/performance-best-practices.adoc[high loads] with high accuracy.
* *Improving*. *Repose* continues to be under https://github.com/rackerlabs/repose/releases[active development].

== Building from source

Install JDK 27 and set `JAVA_HOME` to that installation.
The Gradle wrapper downloads the pinned Gradle distribution and verifies its SHA-256 checksum.

Custom filters use the Jakarta Servlet, Jakarta Inject, and Jakarta REST APIs
(`jakarta.servlet`, `jakarta.inject`, and `jakarta.ws.rs`).
The mock service uses Jersey 4 with Servlet 6.1 and Jakarta REST 4 directly.

Java and Scala sources target Java 27; Scala modules use Scala 3.10.
Rebuild custom filters with this toolchain and the Jakarta APIs before upgrading.
The WADL API checker, WADL tools, and HTTP delegation protocol are built from
source in this repository against Jakarta APIs. The Atom feed service uses
Apache Pekko in place of Akka. XML bindings use JAXB 4 and `jakarta.xml.bind`.
Only the test connector, Deproxy, still needs a Jakarta/Groovy binary adaptation
while resolving test dependencies.

WADL validation and Simple RBAC errors return UTF-8 `text/plain` diagnostics in
the response body. Clients must use the status code and body rather than custom
HTTP/1.1 reason phrases. Successful and delegated response bodies are unchanged.

[source,shell]
----
./gradlew build
----

== Release Versions and GHCR

Release tags use Semantic Versioning. `10.0.0` is the major release for the Java 27,
Scala 3, and Jakarta API migration; custom extensions must be rebuilt.
CI-only changes do not require an application version bump.

The `Publish Repose image` workflow uses the official Temurin 27 runtime image
and locally built application/filter packages. It builds one Linux amd64 image and verifies Java 27,
the application version and an HTTP request through the packaged Echo filter,
then pushes `ghcr.io/anthony-cervantes/repose:10.0.0` and an immutable commit tag.
It runs on matching `v*` tags or manual dispatch, with a 30-minute limit and a
standard Ubuntu runner. Pull requests do not publish images.

For local container packaging, use `./gradlew -PcontainerRelease :repose-aggregator:artifacts:docker:copyPackages :repose-aggregator:artifacts:docker:copyDockerfiles`.
This selects the stable application/package version without invoking the separate
legacy Maven publication and signing configuration.

== Configuration

*Repose* will search for configuration files in the user specified directory.

* The configuration root directory must be user readable.
* The configuration files should be user readable and writable.

Setting the Configuration Root Directory.

* Simply pass the configuration directory to the Java process using the "-c" option.
