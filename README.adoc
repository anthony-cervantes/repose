= REPOSE - The REstful PrOxy Service Engine

*Repose* is an open-source platform that you can use to build stacks of reusable software
components. These components can be leveraged by service developers to perform
common API processing tasks. By using *Repose*'s components rather than creating their
own, service developers can focus on the unique features of their services.

*Repose* is run as a standalone application (either as a Linux service or using the
JAR directly). *Repose* can be run on the same server or on a different server, and
it can be run across multiple servers for horizontal scaling. At its core, *Repose* is a
proxy that allows services to use Enterprise Integration Patterns (EIP).

For more information, check out our link:repose-aggregator/docs/src/asciibinder/recipes/getting-started.adoc[Getting Started with *Repose*] guide.


== Benefits

* *Scalable*. *Repose* is incredibly scalable because it is designed to be stateless.
* *Flexible*. *Repose* is run as a link:repose-aggregator/docs/src/asciibinder/recipes/valve-installation.adoc[standalone Linux service (Valve)].
* *Extensible*. New link:repose-aggregator/docs/src/asciibinder/filters/index.adoc[components]
  are being added all of the time, and you can even build your own
  link:repose-aggregator/docs/src/asciibinder/recipes/custom-filter-for-repose.adoc[custom component].
* *High performance*. *Repose* can handle link:repose-aggregator/docs/src/asciibinder/recipes/performance-best-practices.adoc[high loads] with high accuracy.
* *Improving*. *Repose* continues to be under https://github.com/rackerlabs/repose/releases[active development].

== Building from source

Install Temurin JDK 27.0.1.1+4 and set `JAVA_HOME` to that installation.
The Gradle wrapper downloads the pinned Gradle distribution and verifies its SHA-256 checksum.

Custom filters use the Jakarta Servlet, Jakarta Inject, and Jakarta REST APIs
(`jakarta.servlet`, `jakarta.inject`, and `jakarta.ws.rs`).
The mock service uses Jersey 4 with Servlet 6.1 and Jakarta REST 4 directly.

Java and Scala sources target Java 27; Scala modules use Scala 3.10.
Rebuild custom filters with this toolchain and the Jakarta APIs before upgrading.
The WADL API checker, WADL tools, and HTTP delegation protocol are built from
source in this repository against Jakarta APIs. The Atom feed service uses
Apache Pekko in place of Akka. XML bindings use JAXB 4 and `jakarta.xml.bind`.
Only the test connector, Deproxy, still needs a Jakarta/Groovy binary adaptation
while resolving test dependencies.

WADL validation and Simple RBAC errors return UTF-8 `text/plain` diagnostics in
the response body. Clients must use the status code and body rather than custom
HTTP/1.1 reason phrases. Successful and delegated response bodies are unchanged.

[source,shell]
----
./gradlew build
----

== Release Versions and GHCR

Release tags use Semantic Versioning. `10.0.0` is the major release for the Java 27,
Scala 3, and Jakarta API migration; custom extensions must be rebuilt.
CI-only changes do not require an application version bump.
The `10.1.0` release adds the opt-in
link:repose-aggregator/docs/src/asciibinder/filters/empty-request-filter.adoc[Empty Request Filter].
The `10.1.1` patch release adds opt-in compatibility for the legacy monitor Host format.
The `10.1.2` patch release updates the Java runtime and build JDK to Temurin 27.0.1.1+4.

Docker via GHCR is the only supported deployment path for this fork.
The `Repose Docker` workflow builds one Linux amd64 image using Ubuntu 24.04,
the signed Adoptium Temurin 27.0.1.1+4 runtime and directly staged JVM artifacts.
Gradle produces the Valve JAR, three filter EAR bundles, configuration and license
notices; there are no Repose DEB/RPM intermediates, native deployment tasks, or
remote Maven/Docker Hub publication targets. Local Maven publications remain
available for extension development.
Pull requests and manual runs build and smoke-test the image without publishing.
Pushing a matching `v<version>` tag builds and verifies the image before pushing
the version and source commit tags to `ghcr.io/anthony-cervantes/repose`.
Manual runs never publish or overwrite release tags.

Run the same build and smoke tests locally:

[source,shell]
----
bash scripts/build-container.sh local/repose:dev
----

=== XML Schema 1.1 dependencies

The standard Maven Central `xerces:xercesImpl` JAR does not implement XSD 1.1.
Use Apache Xerces 2.12.2's XSD 1.1 classifier, published to Maven Central by
eXist-db (https://central.sonatype.com/artifact/org.exist-db.thirdparty.xerces/xercesImpl/2.12.2),
with the explicit XPath2 processor, CUP and XML Resolver dependencies.
The shared dependency declaration is `gradle/xerces-xsd11.gradle`.
Java 27 provides the XML APIs instead of the patched legacy XML APIs JAR.
The normal Docker build runs schema 1.0/1.1 assertions and parser feature probes
against the staged Valve and filter bundles, and WADL request routing against
the actual Docker image. The Rackspace repository is limited to Saxon-EE and
Deproxy until their separate migrations are complete.

=== Dependency provenance audit

For legacy repository migrations, use the existing Docker validation workflow
with its `dependency_audit` manual input, or open a PR from an `audit/` branch.
The audit also runs locally with:

[source,bash]
----
bash scripts/audit-dependencies.sh
----

This uses a temporary Gradle user home and reruns archive compilation with
download logging. It builds and verifies a local Docker image without publishing,
then attempts a Scala 3 unit-test coverage report for HTTP Delegation and
compiles the functional test framework to resolve Deproxy.
It reports observed download hosts/paths and hashes of the staged JVM archives,
plus recognizable legacy JARs and shaded classes. Missing log evidence is not
proof that a repository is unused; it is not an SBOM or a full test-suite run.
Normal PR validation and tag publishing keep the existing build path.

The opt-in
link:repose-aggregator/docs/src/asciibinder/recipes/legacy-monitor-host.adoc[legacy monitor Host compatibility]
setting handles the observed `/lb_monitor` Host suffix before HTTP parsing rejects it,
while retaining authentication and strict validation of other malformed Host values.

== Installation

Use Docker with a versioned GHCR image (currently 10.1.2):

[source,shell]
----
docker run --detach --name repose --publish 8080:8080 ghcr.io/anthony-cervantes/repose:10.1.2
----

See the link:repose-aggregator/docs/src/asciibinder/recipes/docker.adoc[Docker deployment recipe].
Legacy package and configuration-management instructions are historical, not supported deployment paths for this fork.

== Configuration

*Repose* will search for configuration files in the user specified directory.

* The configuration root directory must be user readable.
* The configuration files should be user readable and writable.

Setting the Configuration Root Directory.

* Simply pass the configuration directory to the Java process using the "-c" option.
